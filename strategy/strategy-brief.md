# Strategy Brief - F1 Pit Wall Build and Tell

## Core Narrative

Vibe coding can generate dashboards fast.
The hard part is turning those dashboards into embedded, trusted, reusable analytics inside a real product.

F1 Pit Wall is built to show that transition clearly:
- Local Mode proves the speed of the builder workflow.
- Sisense Mode shows how the same experience can move toward product-grade embedded analytics.

## Product Thesis

AI-native builders can already ship UI quickly. They can wire charts, cards, and filters in hours.
What they usually cannot ship quickly is a durable analytics layer:
- governed metrics
- reusable query/model definitions
- consistent filters across views
- embedded analytics behavior that survives product growth

This is the gap Sisense Compose SDK addresses.
Compose SDK is the bridge from local prototype to product-grade embedded analytics while keeping the builder in a code-first workflow.

## Why F1 Pit Wall

F1 telemetry is a strong demo category because it is:
- visual
- familiar
- naturally analytical

Users already understand the core questions:
- Where was time gained or lost?
- When did the gap open?
- Did tyre behavior drive the turning point?

That makes it ideal for storytelling: the audience can focus on architecture value, not domain explanation.

## Mode Story

### Local Mode

Fast builder prototype path:
- run immediately from committed processed data
- no credentials required
- ideal for onboarding, demos, and rapid iteration

### Sisense Mode

Embedded analytics path:
- real SisenseContextProvider boundary
- Compose SDK chart proof point
- env-driven configuration for Sisense URL/token/datasource
- graceful fallback when credentials are missing

The message is intentional:
local mode gets you started fast; Sisense mode gets you product-ready.
